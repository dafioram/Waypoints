Modern C++ for the C++98 Programmer

You know the language. This is what changed in C++11 through C++23, limited to what you'll use weekly. Each block pairs the thing you used to write (grey) with what you write now (blue).

Build with -std=c++20 (or /std:c++20) and you get nearly all of it. Items tagged C++23 need a recent compiler. Skipped on purpose: modules, coroutines, user-defined literals, and most template-metaprogramming internals.

The five habits that change your code most: auto and range-for, unique_ptr instead of new, return by value, lambdas with algorithms, and optional/variant instead of sentinel values.

Stop spelling out iterator typesC++11 / 17

auto deduces the type, range-for walks a container, and structured bindings unpack pairs and structs by name.

std::map<std::string, int>::const_iterator it;
for (it = m.begin(); it != m.end(); ++it)
    use(it->first, it->second);
for (const auto& [name, count] : m)
    use(name, count);

Use const auto& to read, auto& to modify, plain auto for cheap copies like ints.

Initialize containers like arraysC++11

Brace initialization works everywhere, rejects silent narrowing (int x{3.5} is an error), and ends the push_back wall. Members can have defaults right in the class.

std::vector<int> v;
v.push_back(1); v.push_back(2);
std::map<std::string,int> m;
m.insert(std::make_pair("a", 1));
struct P { int n; P() : n(0) {} };
std::vector<int> v{1, 2};
std::map<std::string,int> m{{"a", 1}};
struct P { int n = 0; };
v.emplace_back(3);   // construct in place

Small keyword upgradesC++11

Three old annoyances with one-line fixes: NULL is really 0, plain enums leak names and convert to int, and typedef reads backwards and can't be templated.

f(NULL);                // picks f(int)!
enum Color { RED, GREEN };
typedef std::map<std::string,
    std::vector<int> > Table;
f(nullptr);
enum class Color { Red, Green };  // Color::Red
using Table = std::map<std::string,
    std::vector<int>>;
template<class T> using Vec = std::vector<T>;

Ownership: stop writing deleteC++11 / 14

unique_ptr is a pointer with one owner that frees itself, with zero overhead. shared_ptr is for the rare case of genuinely shared ownership. auto_ptr is gone.

Widget* w = new Widget(3);
if (!setup(w)) { delete w; return; }
// ...leaks if anything throws
delete w;
auto w = std::make_unique<Widget>(3);
if (!setup(*w)) return;   // freed on every exit path

auto cfg = std::make_shared<Config>();  // shared owner
std::vector<std::unique_ptr<Shape>> shapes;

Rule of thumb: no naked new or delete. A raw T* or T& now means "I'm borrowing this, not owning it."

Return big things by valueC++11

Move semantics let a temporary hand over its guts instead of copying them. You spent C++98 writing output parameters to dodge copies; you can stop.

void load(const std::string& path,
          std::vector<char>& out);
std::vector<char> buf;
load("a.bin", buf);
std::vector<char> load(const std::string& path);
auto buf = load("a.bin");   // moved or elided, no copy

auto other = std::move(buf); // explicit transfer
// buf is now valid but empty: don't use its value

std::move doesn't move anything; it just marks "I'm done with this, you may steal from it." Types like unique_ptr, thread and ifstream are move-only. For your own classes, aim for the rule of zero: hold members that manage themselves and write no destructor or copy/move functions at all.

Lambdas replace functor boilerplateC++11 / 14

An inline, anonymous function that can capture local variables. This is what makes the standard algorithms finally pleasant.

struct ByAge {
  bool operator()(const P& a, const P& b) const
  { return a.age < b.age; }
};
std::sort(v.begin(), v.end(), ByAge());
std::sort(v.begin(), v.end(),
  [](const P& a, const P& b) { return a.age < b.age; });

int limit = 18;
auto adults = std::count_if(v.begin(), v.end(),
  [limit](const P& p) { return p.age >= limit; });

Capture lists: [x] copy, [&x] reference, [=]/[&] everything, [p = std::move(ptr)] move in (C++14). Use auto parameters for generic lambdas. Store one with auto f = ... or std::function<int(int)> when you need a uniform type.

Return "maybe", "one of", and "a view"C++17 / 20

Types that say what you mean instead of sentinel values, tagged unions, and defensive string copies.

bool find(int id, User& out);   // or return NULL / -1
union { int i; float f; } u;      // which one is live?
void log(const std::string& s);
void log(const char* s);          // overload to avoid temp
std::optional<User> find(int id);
if (auto u = find(7)) use(*u);

std::variant<int, std::string> v = "hi";
std::visit([](auto&& x){ print(x); }, v);

void log(std::string_view s);     // takes both, no copy
void sum(std::span<const int> xs); // vector, array, C array

string_view and span are non-owning: never keep one past the lifetime of the thing it points at. For recoverable errors, C++23 adds std::expected<T, E>: a value or an error, no exceptions needed.

Containers and utilities you'll reach forC++11 / 20

int a[4];                     // decays, no size()
std::map<K,V> m;              // tree, O(log n)
m.find(k) != m.end();
v.erase(std::remove(v.begin(), v.end(), 0), v.end());
std::array<int, 4> a{};      // a.size(), a.at(), copyable
std::unordered_map<K,V> m;   // hash table, O(1)
m.contains(k);               // C++20
std::erase(v, 0);            // C++20; erase_if(v, pred)

Class hygieneC++11

Say what you mean and let the compiler check it.

class NoCopy {
  NoCopy(const NoCopy&);   // declared, never defined
  void operator=(const NoCopy&);
};
// typo in a virtual override? silently a new function
struct NoCopy {
  NoCopy(const NoCopy&) = delete;
  NoCopy() = default;
};
struct D : Base {
  void draw() const override;   // compile error if it doesn't match
  D(int x) : D(x, 0) {}         // delegating constructor
  using Base::Base;             // inherit constructors
};

Also add final to stop further overriding, noexcept on move operations (containers rely on it), and [[nodiscard]] on functions whose result must not be ignored.

Compute at compile time without template tricksC++11 / 17

constexpr functions are ordinary code (loops included) that the compiler runs when the inputs are known. if constexpr replaces overload and SFINAE gymnastics.

template<int N> struct Fact
{ enum { v = N * Fact<N-1>::v }; };
template<> struct Fact<0> { enum { v = 1 }; };
constexpr int fact(int n) {
  int r = 1;
  for (int i = 2; i <= n; ++i) r *= i;
  return r;
}
static_assert(fact(5) == 120);

template<class T> auto show(T x) {
  if constexpr (std::is_integral_v<T>) return x + 1;
  else return x;      // only compiled when it applies
}

Templates that read like EnglishC++11 / 17 / 20

Variadic templates take any number of arguments, fold expressions collapse them, and concepts replace the enable_if maze with readable requirements and readable errors.

template<class T>
typename boost::enable_if<is_integral<T>, T>::type
gcd(T a, T b);
// sum of N things: overload for 2, 3, 4, ...
template<std::integral T>
T gcd(T a, T b);

auto sum(auto... xs) { return (xs + ...); }  // fold
sum(1, 2, 3);                                // 6

template<class T>
concept Printable = requires(T t) { std::cout << t; };

Threads are in the languageC++11 / 17 / 20

Portable threads, locks, atomics, and futures replace pthreads and platform wrappers. The C++11 memory model is what makes lock-free code well-defined.

pthread_t t;
pthread_create(&t, 0, &worker, arg);
pthread_mutex_lock(&mu); /* ... */ pthread_mutex_unlock(&mu);
std::jthread t([&]{ work(); });   // joins automatically (C++20)

{ std::scoped_lock lk(mu, other_mu); /* deadlock-free */ }

std::atomic<int> hits{0};  ++hits;

auto f = std::async(std::launch::async, compute, 42);
int r = f.get();            // blocks until ready

The pattern holds: locks are RAII objects, never lock/unlock pairs. thread_local gives per-thread variables.

Pipelines and formattingC++20 / 23

Ranges let you pass containers directly to algorithms and chain lazy views. std::format is type-safe printf that works with your own types.

std::sort(v.begin(), v.end());
std::vector<int> sq;
for (size_t i = 0; i < v.size(); ++i)
  if (v[i] % 2 == 0) sq.push_back(v[i] * v[i]);
std::ostringstream os;
os << name << " has " << n << " items";
std::ranges::sort(v);
namespace sv = std::views;
for (int x : v | sv::filter([](int i){ return i % 2 == 0; })
               | sv::transform([](int i){ return i * i; }))
  use(x);                  // lazy: nothing is copied

auto s = std::format("{} has {} items", name, n);
std::print("{:>8.2f}\n", 3.14159);   // C++23

Where to go next

Learn in this order: auto/range-for, smart pointers, move semantics, lambdas, optional/variant, then ranges and concepts. Compile with -Wall -Wextra and a sanitizer (-fsanitize=address,undefined); modern C++ gives the compiler enough information to catch most of your old habits for you.
