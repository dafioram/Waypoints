Rust for C++98 and Python Programmers

Rust gives you C++-level speed and control, with a compiler that proves your memory handling is safe. It also ships with a build tool and package manager, which neither of your languages did. This page covers setup first, then Cargo, then the language, always as "what you did before" next to "what you do now".

Short answers to your build questions: Cargo is the one tool that builds Rust on every platform. It is not CMake, and not quite pip, but it plays both roles. The same Cargo.toml and the same commands work on Linux, macOS and Windows. Only the linker underneath differs.

1. Install Rust

Everything goes through rustup, the toolchain manager (think pyenv for Rust). It installs the compiler rustc, cargo, the standard library, rustfmt (formatter) and clippy (linter), and updates them.

curl --proto '=https' --tlsv1.2 -sSf https://sh.rustup.rs | sh
rustc --version && cargo --version     # check it worked
rustup update                          # later: upgrade everything

On Windows, download and run rustup-init.exe from rustup.rs. It checks for a C++ toolchain and offers to install one.

What Rust needs underneath

Rust compiles its own code, but it hands the final step to your platform's native linker. So you need one installed:

Editor: install rust-analyzer (VS Code extension, or the plugin for your editor) for completion, inline errors and "go to definition".

2. Cargo: build system and package manager in one

Where you juggled Make or CMake, a package source, and a virtualenv, Rust has one tool. A rough map:

JobC++98 worldPython worldRust
Describe the projectMakefile / CMakeLists.txtpyproject.toml / setup.pyCargo.toml
Get librariesSystem packages, vendoring, Conanpip + PyPICargo + crates.io (libraries are called crates)
Pin exact versions—requirements.txt / lock fileCargo.lock, automatic
IsolationManualvenvPer-project by default, no activation step
Run testsgtest + your own runnerpytestcargo test (built in)

The big difference from pip: crates are downloaded as source and compiled with your project, so there are no wheels and no ABI mismatches. The downloads are cached in ~/.cargo (%USERPROFILE%\.cargo on Windows) and shared by all your projects. Build output goes into the project's target/ folder.

A project

hello/
├── Cargo.toml     # name, version, dependencies
├── Cargo.lock     # exact versions used (created on first build)
├── src/main.rs    # entry point (src/lib.rs for a library)
└── target/        # build output, add to .gitignore (cargo new does)
[package]
name = "hello"
version = "0.1.0"
edition = "2024"        # language edition, new projects get the latest

[dependencies]
rand = "0.9"            # means any compatible 0.9.x (semver)
serde = { version = "1", features = ["derive"] }  # optional features

Features are compile-time switches a crate offers, similar to CMake options or pip extras. Editions let the language evolve without breaking old code, and crates on different editions can be mixed freely.

Everyday commands

CommandWhat it does
cargo new nameCreate a project (--lib for a library).
cargo runBuild, then run. Debug mode by default.
cargo build --releaseOptimized build (like -O2), in target/release/.
cargo checkType-check without producing a binary. Much faster; use it while editing.
cargo add randAdd a dependency to Cargo.toml.
cargo updateUpgrade locked versions within what Cargo.toml allows.
cargo testRun unit tests (#[test] functions), integration tests and doc examples.
cargo fmt / cargo clippyFormat code / lint for common mistakes.
cargo doc --openBuild docs for your code and all dependencies. Read this often.

Commit Cargo.lock for applications so everyone builds the same versions. Pure-Rust projects never need CMake or Make.

When C or C++ is involved

  • Using a C library: look for a -sys crate (e.g. libz-sys), which wraps it.
  • Compiling C/C++ inside your build: a build.rs file runs before your crate compiles. The cc crate there invokes MSVC, gcc or clang as appropriate; the cmake crate runs a CMake project. On Windows this is why the C++ Build Tools matter even for Rust.
  • Cross-compiling: rustup target add x86_64-pc-windows-gnu, then cargo build --target x86_64-pc-windows-gnu. Needs a suitable linker for the target.
  • Several crates in one repo: a workspace (a root Cargo.toml listing members) shares one lock file and one target/.

3. The language, by comparison

Grey is C++98 and/or Python; blue is Rust. Run any snippet by pasting it into fn main() { ... } in a cargo new project.

Variables: immutable by default

int n = 0;           // mutable unless const
const int k = 5;
# Python
n = 0                # any name can be rebound
let k = 5;             // immutable
let mut n = 0;         // opt in to change
n += 1;
let x: u64 = 7;        // annotate when it can't be inferred
let n = n.to_string(); // shadowing: a new variable, new type

Functions and expressions

Types on parameters are mandatory. The last expression, without a semicolon, is the return value. if and match are expressions too, so there is no ternary operator.

int add(int a, int b) { return a + b; }
const char* s = n > 0 ? "pos" : "non-pos";
# Python
s = "pos" if n > 0 else "non-pos"
fn add(a: i32, b: i32) -> i32 {
    a + b
}
let s = if n > 0 { "pos" } else { "non-pos" };

Loops

for (int i = 0; i < 10; ++i) {}
for (std::vector<int>::iterator it = v.begin();
     it != v.end(); ++it) show(*it);
# Python
for i in range(10): ...
for i, x in enumerate(v): ...
for i in 0..10 {}              // 0..=10 includes 10
for x in &v { show(*x); }      // borrow; v still usable after
for x in &mut v { *x += 1; }   // modify in place
for (i, x) in v.iter().enumerate() {}
while n < 10 { n += 1; }
let found = loop {             // loop can return a value
    n += 1;
    if n % 7 == 0 { break n; }
};

Iterator chains replace both hand loops and comprehensions. They are lazy and compile down to a plain loop with no overhead. |x| ... is a closure.

std::vector<int> sq;
for (size_t i = 0; i < v.size(); ++i)
  if (v[i] % 2 == 0) sq.push_back(v[i] * v[i]);
# Python
sq = [x * x for x in v if x % 2 == 0]
let sq: Vec<i32> = v.iter().copied()
    .filter(|x| x % 2 == 0)
    .map(|x| x * x)
    .collect();

Structs and methods

Data (struct) and behaviour (impl) are declared separately. &self is a const method, &mut self may modify. There are no constructors: new is just a convention for an ordinary function. There is no inheritance either; sharing behaviour is done with traits (below).

class Point {
  double x, y;
public:
  Point(double x, double y) : x(x), y(y) {}
  double len() const { return std::sqrt(x*x + y*y); }
  void scale(double k) { x *= k; y *= k; }
};
# Python: class Point: def __init__(self, x, y): ...
#[derive(Debug, Clone)]      // auto-generates printing, copying
struct Point { x: f64, y: f64 }

impl Point {
    fn new(x: f64, y: f64) -> Self { Point { x, y } }
    fn len(&self) -> f64 { (self.x * self.x + self.y * self.y).sqrt() }
    fn scale(&mut self, k: f64) { self.x *= k; self.y *= k; }
}
let mut p = Point::new(3.0, 4.0);
p.scale(2.0);
println!("{:?} len={}", p, p.len());

Ownership and borrowing: the big idea

In C++98 you decide who frees memory by convention and hope. In Python a garbage collector decides. Rust makes the rules part of the type system, checked at compile time, with no GC and no runtime cost:

  1. Every value has exactly one owner. When the owner goes out of scope the value is dropped (RAII, like a C++ destructor, automatically).
  2. Assigning or passing a value moves it. The old name becomes unusable.
  3. You can lend a value out with &x (any number of read-only borrows) or &mut x (exactly one writer, and no readers at the same time).
  4. A borrow can never outlive its owner.
void f(std::string s);       // copies
void g(const std::string& s); // borrows
# Python: f(s) shares one object, GC cleans up
// Dangling reference, compiles fine:
std::vector<int> v(3, 1);
int& first = v[0];
v.push_back(4);   // may reallocate
first = 9;        // undefined behaviour
let s = String::from("hi");
f(s);              // moved into f; s is gone
g(&s);             // borrowed; s still usable
f(s.clone());      // explicit deep copy

let mut v = vec![1, 1, 1];
let first = &v[0];
v.push(4);         // ERROR: v is borrowed by `first`
println!("{}", first);   // caught before it ever runs

This is where the learning curve is. The compiler errors are long but usually say exactly what to change. Small integers, floats and bool are copied rather than moved, so they behave as you expect. Smart pointers: Box<T> is unique_ptr, Rc<T> and Arc<T> (thread-safe) are shared_ptr.

Errors: no exceptions, no null

Failure is a value in the return type. Result<T, E> is "a value or an error", Option<T> is "a value or nothing". The ? operator means "if this failed, return the error from my function now".

// C++98: strtol + check endptr, or throw
User* find(int id);        // NULL if missing, caller must check
# Python
try:
    n = int(s) * 2
except ValueError as e:
    print("bad:", e)
fn double(s: &str) -> Result<i32, std::num::ParseIntError> {
    let n: i32 = s.trim().parse()?;
    Ok(n * 2)
}
match double("21") {
    Ok(v) => println!("{v}"),
    Err(e) => eprintln!("bad: {e}"),
}
fn find(id: u32) -> Option<&User> { /* ... */ }

You can't forget to handle an error, because you can't get at the value without going through the Result. For quick scripts, .unwrap() or .expect("msg") crashes (a panic) on failure.

Enums that carry data, and match

enum Kind { CIRCLE, RECT };
struct Shape {
  Kind kind;
  union { double r; struct { double w, h; } rect; } u;
};  // you keep kind and union in sync by hand
# Python: classes plus isinstance checks
enum Shape {
    Circle(f64),
    Rect { w: f64, h: f64 },
    Empty,
}
fn area(s: &Shape) -> f64 {
    match s {
        Shape::Circle(r) => 3.14159 * r * r,
        Shape::Rect { w, h } => w * h,
        Shape::Empty => 0.0,
    }
}

match must cover every variant. Add a new one and the compiler lists every place that needs updating. Option and Result are just enums like this.

Traits and generics

A trait is an interface. Generic functions state what they need (T: PartialOrd), which is like C++20 concepts but required from the start, so errors appear at the definition rather than deep inside an instantiation. Runtime polymorphism (virtual) is dyn Trait.

template<class T>
const T& largest(const std::vector<T>& v);
// needs operator< ... or you find out from a 200-line error
struct Animal { virtual std::string speak() const = 0; };
# Python: duck typing, errors at runtime
fn largest<T: PartialOrd>(xs: &[T]) -> &T {
    let mut m = &xs[0];
    for x in xs { if x > m { m = x; } }
    m
}
trait Animal { fn speak(&self) -> String; }
struct Dog;
impl Animal for Dog {
    fn speak(&self) -> String { "woof".to_string() }
}
let zoo: Vec<Box<dyn Animal>> = vec![Box::new(Dog)];

Strings and collections

std::string s = "hi"; s += " world";
std::vector<int> v;  v.push_back(1);
std::map<std::string,int> m;  m["a"] = 1;
# Python
s = "hi" + " world"; v = [1]; m = {"a": 1}
use std::collections::HashMap;
let lit: &str = "hi";               // borrowed text
let mut s = String::from(lit);      // owned, growable
s.push_str(" world");
let mut v = vec![1, 2, 3];  v.push(4);
let mut m = HashMap::new();  m.insert("a", 1);
println!("{s} {v:?} {}", m["a"]);   // {:?} = debug print

&str versus String is like string_view versus std::string. All text is UTF-8. println! ends in ! because it's a macro; the compiler checks the format string.

Modules instead of headers

// util.h with include guards, util.cpp separately
#include "util.h"
# Python
import util
from util import helper
// src/util.rs  (one file, no header)
pub fn helper() {}      // pub = visible outside the module

// src/main.rs
mod util;               // declares and finds util.rs
use util::helper;
use rand::Rng;          // from a dependency in Cargo.toml

4. What will surprise you

  • Everything is private and immutable until you say otherwise (pub, mut).
  • No implicit conversions. let x: i64 = my_i32; fails; write my_i32 as i64 or i64::from(my_i32).
  • No overloading and no default arguments. Use different names, or a builder or Option.
  • Integer overflow panics in debug builds and wraps in release builds. Use checked_add or wrapping_add when it matters.
  • Data races are compile errors. Threads (std::thread::spawn) only accept data that is safe to share (the Send and Sync traits), and mutable shared state needs Arc<Mutex<T>>.
  • unsafe { } exists for raw pointers and C calls. It switches off only some checks, and it's rare in application code.

5. Where to go next

Read The Rust Programming Language (free online, called "the book"), chapters 4 on ownership and 9 on errors first. Do the small exercises in rustlings (cargo install rustlings), and keep Rust by Example open as a cookbook. While working, run cargo clippy often and read its suggestions: it teaches idiomatic Rust.
